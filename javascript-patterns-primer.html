Hashmaps without the fog.

You do not need advanced algorithms for the interview described. This page gives you a small mental model for the two tools that often make an easy problem shorter: Map and Set.

Use this as a five-minute explanation, then type one example.
Do not memorize every method. Remember the question each tool answers.

Choose the tool by the question

If the problem asks…Reach for…Plain-English idea
“Have I seen this value?”SetKeep one copy of each value and check membership quickly.
“How many times?” or “What belongs to this key?”Map or objectStore a key next to its count, index, or other value.
“Compare every pair” and the input is tinyTwo loopsThe direct solution is fine. Clear code beats a clever trick.
“The data is sorted” or can be sortedSort + two pointersMove one pointer from each side instead of checking every pair.
Interview scope: Start with the direct two-loop twoSum solution in the lab. Treat the Map version below as an optional stretch and a way to explain a faster lookup.

The core shapes

Set: remember values

has asks whether a value is already present. add remembers it.

const seen = new Set();
if (seen.has(value)) {
  return true; // duplicate found
}
seen.add(value);

Map: remember key → value

get reads a value. set stores one. The key can be a number or string.

const counts = new Map();
const oldCount = counts.get(letter) || 0;
counts.set(letter, oldCount + 1);

Three facts to say aloud

  1. “I will store information I have already seen.”
  2. “For each item, I will look up the key I need.”
  3. “This usually changes repeated searching from O(n²) to O(n), using extra memory.”

If the interviewer has not asked about complexity, one sentence is enough: “I trade some memory for a faster lookup.”

Worked example: twoSum with a Map

The lab’s nested-loop answer is completely acceptable for a small exercise. This version shows the lookup pattern: for the current number, ask whether its partner has already been seen.

function twoSum(numbers, target) {
  const seen = new Map(); // number → index

  for (let i = 0; i < numbers.length; i++) {
    const partner = target - numbers[i];
    if (seen.has(partner)) {
      return [seen.get(partner), i];
    }
    seen.set(numbers[i], i);
  }

  return [];
}

Trace one example

numbers = [2, 7, 11, 15], target = 9

At index 0, partner is 7; it is not seen, so store 2 → 0. At index 1, partner is 2; it is seen, so return [0, 1].

What can go wrong?

Store after checking, so an item cannot pair with itself. Return [] after the loop when no pair exists.
